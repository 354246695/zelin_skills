# bilingual-doc：中英对照 HTML 生成

把一份外语技术文件做成单文件、可直接打开的中英对照 HTML，供精读和按行号定位修改。

核心价值三条（缺一即返工）：

- **行号可追溯**：每段原文标注行区间，读者能定位源文件去改。
- **出处可核查**：非平凡论断标来源；术语先查仓库再落笔，查不到就写明。
- **无删节**：原文行区间全覆盖，读者不需要回源文件补读。

适用：SKILL.md、提示词、协议/接口文档、配置说明等「要读懂并准备修改」的文本文件。
不适用：已基本是中文的文件；用户只要摘要或讲解页的场景（讲解页归 archify）。

## 产物

- 单个自包含 HTML，无外部依赖，`file://` 直接打开。
- 版式：复制本包 `assets/template.html` 为起点改写，不要凭记忆重写 CSS。
- 输出位置：遵循当前项目的文档放置规则；没有规则就先问用户。命名跟随目标目录已有风格。
- 多个源文件可合在一个产物里：一章一文件，第二条并行线用 `sec-b` 配色。

## 工作流

### 1. 定位与取证

- 通读源文件全文，带行号，禁止只读开头。
- 源文件在 git 仓库：记 `git log -1 --format="%h %ad %s" --date=short` 和 `git status --short`；工作区不干净必须写进页头。不在仓库：页头写「无版本基线」加核对日期。
- 记下源文件总行数，第 7 步要对账。
- 源文件超过约 1000 行：先和用户确认收录范围（全文/选段），确认结果写进页头。

### 2. 术语查证

- 拿不准的术语、编号、专名：在源仓库 grep 核实（决策登记、代码、docs）。查到标「出处：文件+行号」；查不到写「查不到对应登记」。
- 禁止凭印象断言仓库里的事实。

### 3. 分块

- 按原文标题层级切块，一块一个行区间；超长节（约 40 行以上）按子结构再切。
- 代码块（bash / JSON / YAML 等）独立成 `<pre>`，不进对照对。

### 4. 填充

- 左列原文：只加排版（标题、列表、`code` 标签），措辞与内容零改动。
- 右列译文：逐段忠实翻译；代码标识、字段名、文件名、CLI 参数保留英文原名。
- 原文已是中文的单元格：照录并注明「原文即中文」。
- 对照清单（参数表、引用文件）用全宽表格：列分「原文说明 / 中文说明」。
- 自己的观察、查证、疑点只进黄色注释框，框内标明「我的观察/判断」。
- 代码块上方写行区间和「两侧一致」。

### 5. 写入

- 产物预计超过约 800 行：先写骨架加占位符注释（`<!-- TODO: ... -->`），再分次 edit 填充。单次 write 装不下硬塞会中断。

### 6. 结构自检

对产物跑（PowerShell，`$f` 换成实际产物路径）：

```powershell
$f = "<产物.html>"
$c = Get-Content -Raw -Encoding UTF8 $f
foreach ($t in 'div','ul','ol','table','pre','section') {
  "$t : $([regex]::Matches($c,"<$t\b").Count) / $([regex]::Matches($c,"</$t>").Count)"
}
$ids   = [regex]::Matches($c,'id="(s\d[a-z0-9-]*)"') | ForEach-Object { $_.Groups[1].Value } | Sort-Object -Unique
$hrefs = [regex]::Matches($c,'href="#(s\d[a-z0-9-]*)"') | ForEach-Object { $_.Groups[1].Value } | Sort-Object -Unique
$hrefs | Where-Object { $ids -notcontains $_ }     # 输出必须为空
Select-String -Path $f -Pattern 'TODO:'             # 输出必须为空
```

- 配平计数两边相等；锚点缺项为空；占位符清零。
- 转义抽查：源文里的 `<` `>` `&` 在产物里必须以 `&lt;` `&gt;` `&amp;` 出现。

### 7. 内容自检与交付

- 行区间对账：各块行区间首尾相接，覆盖 1 到总行数（或确认过的收录范围），无空洞无重叠。
- 术语一名一叫：全文搜近义词，同一术语只用一个叫法。
- 「我的话」只在注释框和交付说明里，不进原文列。
- 交付说明写四件事：通过的自检；剩余风险（至少写「译文未经第二人校对」「行号随源文件改动会漂移」两条）；发现的疑点；需要用户决定什么。

## 硬规则

1. 左列只放原文；自己的话只进注释框。
2. 无删节，行区间全覆盖。
3. 非平凡论断标出处；查不到写明。
4. 代码标识、字段名、文件名保留英文。
5. 行号基于页头基线；交付时提醒漂移风险。
6. 不主动 commit / push。

## 范例

- `D:\0_workspace\01_docs\04_项目文档\skill-optimize-提示词中英对照.html`
- `D:\0_workspace\01_docs\04_项目文档\aae-评测用例生成skill-中英对照.html`

两个范例都是完整跑通本流程的产物。文件不存在时忽略，不影响流程。
